ProofFlow 不具合報告 — 利用者・テスターからのエラー報告を不具合票にする
====================================================================

自動テストでは見つからない不具合は、実際に使った人が見つけます。ProofFlow 不具合報告は、エラー画面や文章から
「発生日時・環境・再現手順・期待と実際・スクリーンショット」のそろった報告を作り、ProofFlow 個人情報マスクを
かけてから不具合票（Defect）にします。不具合票になった後は、通常どおり 修正 → 再テスト → Release Gate に流れます。

■ 1. チーム内から報告する（ログインしている人）
画面左の「不具合報告」→「新しい報告」。
1. 何が起きたか: 件名と、起きたことを文章のまま書きます。「文章から再現手順を作る」を押すと手順の下書きができます
   （書いていない手順を推測で足すことはありません。必ず確認・修正してください）。手順は追加・並べ替え・削除できます。
2. 発生日時: 「今起きた」を押すか、日時を入力します（タイムゾーン付きで記録。わからなければ空欄のままで構いません）。
3. 環境: ブラウザ・OS・画面サイズ・言語は自動で入ります。端末名は推測しません。アプリのバージョンや発生ページは手で入力。
4. 添付: スクリーンショット（PNG / JPEG。他の画像形式は PNG に変換）とテキストのログを最大 10 件。
   画像の撮影日時・位置情報などのメタデータは保存前に削除、テキストは個人情報をマスクしてから保存します。
5. 個人情報マスクの確認: 右側に「送信される内容（マスク後）」が日本語 / English で表示されます。
   メールアドレス・電話番号は「そのまま残す」を選べます。API キー・トークン・パスワード・ワンタイムコード・カード番号は常にマスクされます。
6. 「既存の不具合と照合」で似ている未解決の不具合が出たら、その不具合に証跡として追加することもできます（同一とは限りません）。
7. 重要度・優先度・リリース候補・環境を選び、「マスク後の内容と添付を確認しました」にチェックして送信。
同じ報告を二重に送っても（通信エラーで再送した場合など）、不具合票は 1 件だけです。

■ 2. 外部の利用者・β テスターから受け付ける（ログイン不要）
「不具合報告」→「外部受付フォーム」→「受付フォームを作る」（QA Lead 以上）。
- 名前、既定の重要度・優先度（報告者は重要度を選べません）、リリース候補、1 時間あたりの受付上限を決めます。
- 作成直後に表示される URL（https://あなたのサーバー/intake/…#token=pfi_…）を報告者に渡します。URL は一度しか表示されません。
  なくした場合や広まりすぎた場合は「無効化」して作り直してください。
- 報告者には受付番号（BR-…）だけが返ります。既存の不具合の一覧や内容は見えません。
- 1 時間の上限を超えると受け付けを一時停止します（HTTP 429）。

■ 3. 受け付けた報告を見る
「不具合報告」→「受け付けた報告」。受付番号を押すと、日本語 / 英語のレポート（Markdown でダウンロード可）、添付、
似ている不具合の候補が見られます。不具合票の画面からも「不具合報告」へのリンクと添付（証跡）が見られます。
添付は不具合票の証跡として長期保持（release_evidence、既定 365 日）になります。

■ 4. ChatGPT / Codex から報告する
MCP Plugin の submit_bug_report を使うと、エージェントが見つけたエラーを報告として登録できます（添付は不可）。

■ 注意
- 自動検出は完全ではありません。送信前に必ず目視で確認してください。画像の中の顔・QR コード・他人との会話・顧客データ・
  氏名は自動では検出できません（画像の塗りつぶし機能は今後の予定です）。
- GitHub / Jira / メールなど外部サービスへの自動送信、AI による報告文の自動作成は、この版にはありません。
